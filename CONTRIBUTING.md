# Contributing to the usdAeco family

Start with the [family index](docs/family/README.md) and generate a repository with `new-library`. Follow [S01–S28](docs/repo-conventions.md): the fixed README headings, library manifest and exact dependency pins, flat schema module and Python validator sibling, source-importable tools and tests, use-case story and committed example results. Declare owned namespaces and class prefixes. Requirements describe supported version ranges; pins record the releases actually checked. The core's design model and ADRs govern identity, classification, vanilla composition and the separation of drivers from derived opinions.

Run the gate from the repository root with an existing USD-enabled Python: `env -u PYTHONPATH python check.py`, then `env -u PYTHONPATH python -m pytest -q`. When loading core validators, supply `PYTHONPATH=../usdaeco-core:.` after `env -u PYTHONPATH`, put the core's built resources first in `PXR_PLUGINPATH_NAME`, and fail if `usdAecoValidators` cannot be imported. The gate includes structure lint and prints `N checks, M failed, K not run`; unexecuted checks retain their cause. Run `nix flake check --no-write-lock-file` once with externally supplied source overrides where required. Record unavailable inputs as unproven work.

Propose changes to shared schema contracts through an architecture decision record in the core's `docs/adr/`, describing the referent or aspect, namespace ownership, alternatives, compatibility and a small example. Use the existing [core ADRs](https://github.com/criad-com/usdaeco-core/tree/v0.9.2/docs/adr) as precedents. An implementation includes a version bump, changelog, declared applicability and fallback types, and a seeded defect for each validator. Author editable drivers and derived output in separate layers; regenerate owned schema outputs and the example through the shared tools.

Family code uses MIT; preserve the existing licence file and attribution. Three third-party exceptions remain explicit: IfcOpenShell is LGPL-3.0 and imported only; OCCT is LGPL-2.1 and dynamically linked; the Bonsai Blender-side scripts are GPL-3.0-or-later under `blender/`. Each repository documents its actual dependencies and every additional licence path. [S01](docs/repo-conventions.md#licences) also recognizes complete Apache-2.0 and BSD-3-Clause terms in existing releases, without changing their licences. New contributions do not relicense upstream code or erase notices.

Submit a small branch and one pull request per repository, with measured acceptance results and a Deviations section. Keep private terms, deployment details and local paths out of code, fixtures, prose and commits; run `usdaeco-check publication .` before review. Update the [generated family index](docs/publishing.md) when the train changes. Publication requires explicit approval for the particular repository and tag: prepare and review `usdaeco-publish --report` first, and only then use `--push` with the approved explicit remote. The metadata repository stays private; the [board export](https://github.com/criad-com/usdaeco-board/blob/v0.1.2/docs/static-export.md) supplies the static reader view.
